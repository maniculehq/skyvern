This page walks you through giving an AI coding tool (Cursor, Claude Code, Claude Desktop, Windsurf, Codex, OpenClaw, or Hermes) live access to a real browser through Skyvern's MCP server. By the end, your assistant can fill forms, download files, scrape pages, and run any other Skyvern action without you copying API calls back and forth, and you can switch between Skyvern Cloud and a local server whenever you want.

If you're looking for the conceptual overview or the Cloud UI walkthrough, see [MCP Server](/cloud/getting-started/mcp). This page is the developer-flow recipe.

## Prerequisites

- Python `>=3.11,<3.14`, matching the package metadata in `pyproject.toml`.
- One of the supported MCP clients installed: Cursor, Claude Code, Claude Desktop, Windsurf, Codex, OpenClaw, or Hermes.
- A Skyvern API key. Get one at [app.skyvern.com/settings](https://app.skyvern.com/settings/) for Cloud, or generate a local key with `skyvern init`.

```bash
pip install skyvern
```

## 1. Pick local or cloud

`skyvern init` is the interactive wizard. It asks whether you want to run against Skyvern Cloud or a local server, writes the right env vars to a `.env` file in your current working directory, and offers to register the MCP server with the AI tools it finds installed.

```bash
skyvern init
```

Two paths from the prompt:

- **Cloud.** Paste your Skyvern API key when asked. Subsequent MCP calls hit `https://api.skyvern.com` and use Skyvern's hosted browser pool.
- **Local.** The wizard sets up a local Skyvern server on `http://localhost:8000` and generates a local API key. You'll need to keep `skyvern run server` running in another terminal whenever you want to use the local profile.

You can re-run `skyvern init` later to switch the default; nothing is locked in.

## 2. Register the MCP server with your tool

If the wizard didn't catch a tool you use (or you skipped that step), `skyvern setup` is the standalone command. It edits the right config file for each tool, backing up the previous version first.

```bash
# One per tool, run only the ones you want.
skyvern setup cursor
skyvern setup claude-code
skyvern setup claude
skyvern setup windsurf
skyvern setup openclaw
skyvern setup hermes
```

The setup commands live in `skyvern/cli/setup_commands.py`. Cursor, Claude Code, and Windsurf get JSON `mcpServers` entries for stdio. Claude Desktop uses an `npx mcp-remote` bridge for the remote profile unless you pass `--local`. OpenClaw writes its `mcp.servers` JSON5 shape, and Hermes writes YAML. Codex is not registered by `skyvern setup`; add it manually if needed, then `skyvern mcp switch` can update `~/.codex/config.toml`.

<Note>
Before overwriting an existing config, `skyvern setup` copies it to `<config>.bak-YYYYMMDD-HHMMSS-mmmmmm` next to the original (`setup_commands.py:351-365`, using `shutil.copy2` so file permissions are preserved). The original is overwritten in the format that tool uses (JSON for JSON clients, YAML for Hermes; OpenClaw JSON5 is normalized to JSON), and the backup is your rollback. The CLI prints `Backup saved to <path>` after a successful write so you can find it.

If your existing config can't be parsed (malformed JSON, unexpected schema), `skyvern setup` aborts with `"Cannot parse <path>. Fix the JSON and re-run."` and never writes. No backup is created in that case because nothing is being overwritten.
</Note>

After registering, restart the tool. The MCP server should show up in its tools list within a few seconds.

## 3. Verify the connection

Open the AI tool's MCP debug panel, or just ask the assistant a question that requires the browser. Something like:

> "Use Skyvern to grab the title of the top story on Hacker News right now."

The assistant should call a Skyvern tool, return the title, and (if you watch the run) you'll see the matching record on the [Runs page](https://app.skyvern.com/history) or in your local Skyvern UI.

If the assistant says it can't find a Skyvern tool, the most common causes:

- The tool wasn't restarted after setup.
- The config edit was rejected because the file had a syntax error. `skyvern setup <tool>` won't overwrite a broken config; fix the file and re-run.
- The assistant is using an outdated tool list cache. Reload it from the tool's UI.

## 4. Manage profiles

Most people only have one MCP profile, but if you flip between work and personal accounts, or local and cloud, save them and switch in one command.

```bash
skyvern mcp profile save personal-cloud
skyvern mcp profile save work-local
skyvern mcp profile list
```

Saved profiles live under `~/.config/skyvern/mcp-profiles/<slug>.json` (or `%APPDATA%\skyvern\mcp-profiles` on Windows) with `0600` permissions. Each profile records `name`, `api_key`, and `base_url`, with no other state.

To switch which profile a tool uses:

```bash
skyvern mcp switch
```

The command reads each tool's current MCP config (Cursor, Claude Code global and project, Claude Desktop, Windsurf, Codex, OpenClaw, Hermes), shows you what's currently wired up, and lets you point any of them at a different saved profile. The detection logic, including the `mcp-remote` bridge clients use, is in `skyvern/cli/mcp_commands.py`.

## 5. Custom MCP clients

If your tool isn't on the list, register Skyvern's MCP server manually in its config. The stdio entry that works for arbitrary clients:

```json
{
  "mcpServers": {
    "Skyvern": {
      "command": "python",
      "args": ["-m", "skyvern", "run", "mcp"],
      "env": {
        "SKYVERN_BASE_URL": "https://api.skyvern.com",
        "SKYVERN_API_KEY": "YOUR_SKYVERN_API_KEY"
      }
    }
  }
}
```

Replace `python` with the absolute path to the interpreter where you installed Skyvern if your tool can't resolve it from `PATH`. For HTTP clients, use:

```json
{
  "mcpServers": {
    "Skyvern": {
      "type": "http",
      "url": "https://api.skyvern.com/mcp/",
      "headers": { "x-api-key": "YOUR_SKYVERN_API_KEY" }
    }
  }
}
```

These are the two underlying transports. Client-specific files may wrap them differently.

## What the assistant can do

The MCP server exposes Skyvern's primary surface as tools. The assistant can run tasks, run workflows, inspect blocks and folders, fetch credentials, manage browser sessions, list schedules, manage scripts, and query the run timeline. The full set of registered tool modules lives in `skyvern/cli/mcp_tools/` (one file per surface area). When an MCP client asks Skyvern what tools it has, that directory is the answer.
