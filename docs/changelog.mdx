<Update label="v1.0.29 — April 2, 2026" description="SQLite-first server mode, parallel loops, webhook trigger, and more">

## New features

- **SQLite-first server mode** — `skyvern run server` now works out-of-the-box with zero configuration, using SQLite by default. No PostgreSQL setup required for local development or self-hosting. ([#5302](https://github.com/Skyvern-AI/skyvern/pull/5302))

- **Parallel For-Loop Execution** — For-loop blocks can now execute iterations in parallel rather than sequentially, with configurable concurrency limits. Dramatically reduces runtime for data-heavy workflows. ([#5412](https://github.com/Skyvern-AI/skyvern/pull/5412))

- **Webhook Trigger Endpoint** — New `POST /v1/workflows/{permanent_id}/trigger` endpoint triggers a workflow run via HTTP webhook, making it easy to kick off automations from external systems. ([#5292](https://github.com/Skyvern-AI/skyvern/pull/5292))

- **Multi-Tab Browser Management in MCP** — MCP clients can now open, switch between, and close browser tabs during an automation session. ([#5313](https://github.com/Skyvern-AI/skyvern/pull/5313))

- **iframe Support for SDK, CLI, and MCP** — Skyvern can now interact with content inside iframes, a common pattern on legacy enterprise portals and embedded widgets. ([#5319](https://github.com/Skyvern-AI/skyvern/pull/5319))

- **Network Request Interception for MCP/CLI** — MCP and CLI tools can now capture request/response bodies, intercept routes, and inspect network traffic during automation runs. ([#5370](https://github.com/Skyvern-AI/skyvern/pull/5370))

- **MCP Batch Observe/Execute Tools** — New batch tools let MCP clients observe page state and queue multiple actions in a single round-trip, improving agent loop efficiency. ([#5386](https://github.com/Skyvern-AI/skyvern/pull/5386))

- **Clipboard Read/Write MCP Tools** — MCP clients can now read from and write to the system clipboard. ([#5365](https://github.com/Skyvern-AI/skyvern/pull/5365))

- **NAT Egress Proxy for Webhook Delivery** — Webhook callbacks are now sent from static IP addresses, making it easier to whitelist Skyvern in firewall rules. ([#5392](https://github.com/Skyvern-AI/skyvern/pull/5392))

- **Stealth Chromium Browser Sessions** — Browser sessions can now use a stealth-hardened Chromium build to reduce bot-detection fingerprinting. ([#5329](https://github.com/Skyvern-AI/skyvern/pull/5329))

- **Parameter Autocomplete in Workflow Blocks** — Workflow text blocks now autocomplete parameter names as you type `{{`, surfacing available parameters and upstream block outputs. ([#5293](https://github.com/Skyvern-AI/skyvern/pull/5293))

- **Duration Column in Past Runs** — The per-workflow Past Runs table now shows run duration alongside status and timestamps. ([#5419](https://github.com/Skyvern-AI/skyvern/pull/5419))

- **Schedule Endpoints in OpenAPI** — Schedule management endpoints are now included in the OpenAPI specification and generated SDKs. ([#5408](https://github.com/Skyvern-AI/skyvern/pull/5408))

- **/smoke-test Skill** — New built-in skill that runs a smoke test against a target URL using Skyvern, suitable for CI/CD quality gates. ([#5317](https://github.com/Skyvern-AI/skyvern/pull/5317))

## Improvements

- MCP observe/execute batch tools with AI speed optimizations. ([#5386](https://github.com/Skyvern-AI/skyvern/pull/5386))
- Retry selector lookup before falling back to AI in cached scripts. ([#5385](https://github.com/Skyvern-AI/skyvern/pull/5385))
- Page URL now included in agent action summaries for the script reviewer. ([#5384](https://github.com/Skyvern-AI/skyvern/pull/5384))
- `run_with` field is now returned in `GET /v1/runs/{id}` responses. ([#5380](https://github.com/Skyvern-AI/skyvern/pull/5380))

## Bug fixes

- WorkflowTriggerBlock now works correctly in cached scripts. ([#5320](https://github.com/Skyvern-AI/skyvern/pull/5320))
- MCP workflow updates no longer wipe credential parameters. ([#5398](https://github.com/Skyvern-AI/skyvern/pull/5398))
- Credential block references are preserved during MCP workflow updates. ([#5344](https://github.com/Skyvern-AI/skyvern/pull/5344))
- Default login prompt applied to MCP-created login blocks. ([#5342](https://github.com/Skyvern-AI/skyvern/pull/5342))
- File download blocks inside for-loops are now correctly cached. ([#5323](https://github.com/Skyvern-AI/skyvern/pull/5323))
- Nested for-loop script block persistence fixed. ([#5404](https://github.com/Skyvern-AI/skyvern/pull/5404))
- ISO datetime strings preserved in workflow YAML loading. ([#5421](https://github.com/Skyvern-AI/skyvern/pull/5421))
- TextPromptBlock error handling improved with better LLM diagnostics. ([#5333](https://github.com/Skyvern-AI/skyvern/pull/5333))

</Update>

<Update label="v1.0.22 — February 26, 2026" description="Adaptive caching, Workflow Trigger block, CLI signup, and more">

## New features

- **Adaptive Caching (Script Generation)** — Skyvern can now learn from repeated workflow runs and generate cached scripts that speed up future executions. When a block runs successfully, Skyvern records a reusable script and replays it on subsequent runs, falling back to the AI agent only if the script fails. ([#4908](https://github.com/Skyvern-AI/skyvern/pull/4908), [#4916](https://github.com/Skyvern-AI/skyvern/pull/4916), [#4917](https://github.com/Skyvern-AI/skyvern/pull/4917), [#4920](https://github.com/Skyvern-AI/skyvern/pull/4920), [#4922](https://github.com/Skyvern-AI/skyvern/pull/4922), [#4931](https://github.com/Skyvern-AI/skyvern/pull/4931))

- **Workflow Trigger Block** — A new block type that lets one workflow trigger another from within the workflow editor. Chain workflows together as building blocks for complex automations. ([#4885](https://github.com/Skyvern-AI/skyvern/pull/4885))

- **Browser-based CLI Signup** — New users can sign up for Skyvern Cloud directly from the CLI. Running `skyvern signup` opens a browser flow that creates your account and stores your API key locally. ([#4925](https://github.com/Skyvern-AI/skyvern/pull/4925))

- **Interactive ngrok Tunnel** — `skyvern browser serve` can now create an ngrok tunnel automatically, making it easy to expose your local browser to Skyvern Cloud without manual network configuration. ([#4924](https://github.com/Skyvern-AI/skyvern/pull/4924))

- **South Korea Proxy Location** — Added `RESIDENTIAL_KR` as a proxy geolocation option for automations targeting South Korean websites. ([#4918](https://github.com/Skyvern-AI/skyvern/pull/4918))

- **Downloaded Files Tab** — Browser session detail pages now include a Downloaded Files tab for viewing and accessing files captured during a session. ([#4911](https://github.com/Skyvern-AI/skyvern/pull/4911))

- **CDP Proxy Authentication** — Remote browser connections now support authenticated proxies via the CDP `Fetch.authRequired` protocol. ([#4936](https://github.com/Skyvern-AI/skyvern/pull/4936))

- **Remote Browser Download Interception** — File downloads triggered by XHR requests and other non-navigation events are now captured when using remote CDP browser connections. ([#4906](https://github.com/Skyvern-AI/skyvern/pull/4906), [#4921](https://github.com/Skyvern-AI/skyvern/pull/4921), [#4934](https://github.com/Skyvern-AI/skyvern/pull/4934))

## Improvements

- **Renamed "Login-Free" to "Saved Profile"** — Clearer terminology throughout the UI. Browser session checkbox wording has also been improved. ([#4914](https://github.com/Skyvern-AI/skyvern/pull/4914))

- **TOTP Verification Improvements** — Better timer handling, expired code retry, 2FA banner suppression, and more reliable goal-text extraction during TOTP flows. ([#4860](https://github.com/Skyvern-AI/skyvern/pull/4860))

- **TOTP Webhook includes `workflow_permanent_id`** — Easier to identify which workflow is requesting a 2FA code. ([#4871](https://github.com/Skyvern-AI/skyvern/pull/4871))

- **Consolidated Gemini 3 Pro Model Key** — `VERTEX_GEMINI_3_PRO` now auto-resolves to the latest version, so you no longer need to update config when Google releases point versions. ([#4926](https://github.com/Skyvern-AI/skyvern/pull/4926))

- **Browser Rotation for Remote Connections** — Remote browser environments now support context rotation, improving reliability for long-running automations. ([#4929](https://github.com/Skyvern-AI/skyvern/pull/4929))

## Bug fixes

- Fixed a race condition where final task status could be overwritten by a late-arriving non-final status. ([#4928](https://github.com/Skyvern-AI/skyvern/pull/4928))
- Conditional blocks no longer crash when evaluating empty or null parameters. ([#4907](https://github.com/Skyvern-AI/skyvern/pull/4907))
- Browser sessions using `FORCE_BROWSER_SESSION` no longer time out prematurely. ([#4903](https://github.com/Skyvern-AI/skyvern/pull/4903))
- SVG-based captcha text is now correctly extracted during DOM scraping. ([#4880](https://github.com/Skyvern-AI/skyvern/pull/4880))
- MCP remote tool handlers now route to the correct API environment. ([#4869](https://github.com/Skyvern-AI/skyvern/pull/4869))
- MCP remote auth token comparison no longer fails on encrypted tokens. ([#4863](https://github.com/Skyvern-AI/skyvern/pull/4863))
- `skyvern quickstart` now handles local PostgreSQL without a pre-existing `skyvern` role. ([#4878](https://github.com/Skyvern-AI/skyvern/pull/4878))
- WebSocket URLs through ngrok tunnels now rewrite correctly for live browser streaming. ([#4927](https://github.com/Skyvern-AI/skyvern/pull/4927))
