---
title: "schedules_disable"
description: "Pause a schedule without deleting it."
slug: sdk-reference/workflow-schedules/disable-schedule
---

Pausing keeps the schedule (cron, timezone, parameters, name, history) intact while telling the scheduling backend to stop firing it. Use this when you expect to resume later. To remove a schedule for good, call [`schedules_delete`](./delete-schedule).

If the backend call fails, the DB toggle is rolled back so the row stays consistent with what the scheduling service believes.

<CodeGroup>
```python Python
resp = await client.schedules_disable(
    workflow_permanent_id="wpid_invoices",
    workflow_schedule_id="ws_abc123",
)
assert resp.schedule.enabled is False
```

```typescript TypeScript
const resp = await skyvern.schedulesDisable("wpid_invoices", "ws_abc123");
console.assert(resp.schedule.enabled === false);
```
</CodeGroup>

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `workflow_permanent_id` | `str` | Yes | The workflow's permanent id. |
| `workflow_schedule_id` | `str` | Yes | The schedule id (`ws_...`). |
| `request_options` | `RequestOptions` | No | Per-request configuration (see below). |

### Returns `WorkflowScheduleResponse`

`schedule.enabled` is `False` on success. `next_runs` is computed from the cron expression but the backend will not actually fire the schedule until it is enabled again.

### Errors

- `404 Not Found` — workflow or schedule id is not visible to the calling org, or the schedule belongs to a different workflow.
- `501 Not Implemented` — scheduling is disabled in this build.
- `502 Bad Gateway` — backend sync failed. The DB toggle was reverted; safe to retry.

### Related

- [`schedules_enable`](./enable-schedule) — resume.
- [`schedules_delete`](./delete-schedule) — remove instead of pausing.
