title: Adaptive Caching
subtitle: Speed up repeated workflow runs with @cached scripts

Adaptive Caching learns from successful AI-driven runs and generates cached Python functions that replace AI calls on future runs. When a cached function fails (e.g., a website layout changed), Skyvern automatically falls back to the AI agent and regenerates a new cached version.

This feature was introduced in v1.0.22 and is available for `navigation`, `action`, `extraction`, `login`, `file_download`, and other browser-interaction blocks.

---

## How it works

1. **First run** — Skyvern uses the AI agent to complete each block. On success, it records the actions as a cached Python function.
2. **Subsequent runs** — Skyvern tries the cached function first. If it succeeds, no AI call is made — the run is faster and cheaper.
3. **Cache miss / failure** — If the cached function raises an exception (e.g., a selector is stale), Skyvern falls back to the AI agent, completes the block, and regenerates a fresh cached function.

This "record and replay" pattern is transparent: you do not need to change your workflow definition. Adaptive Caching is enabled by default for all applicable block types.

---

## Which blocks are cached

Not all block types participate in Adaptive Caching. The table below shows which blocks are eligible and which always run via the AI agent.

| Eligible for caching | Never cached (always AI) |
|---|---|
| `navigation` | `conditional` |
| `action` | `wait` |
| `extraction` | `code` |
| `login` | `text_prompt` |
| `file_download` | `http_request` |
| `for_loop` (and its child blocks) | `send_email` |
| `task` | `validation` |
| `task_v2` | `human_interaction` |
| | `workflow_trigger` |
| | `goto_url` |
| | `file_url_parser` |
| | `pdf_parser` |
| | `print_page` |
| | `upload_to_s3` |
| | `download_to_s3` |
| | `file_upload` |

<Note>
`conditional` blocks are never cached by design — branch conditions must be evaluated at runtime against the current state. However, the blocks **inside** each branch are individually cached once that branch has been executed at least once. See [Conditional branches and progressive caching](#conditional-branches-and-progressive-caching) below.
</Note>

## @workflow decorator

The `@workflow` decorator marks the entry-point function of a Skyvern script. It is required when writing a script that will be executed via `skyvern run` or the Scripts API.

```python
from skyvern import workflow

# Decorator signature:
# workflow(title=None, totp_url=None, totp_identifier=None, webhook_url=None, max_steps=None)

@workflow(title="My workflow")
async def run_workflow(parameters: dict):
    ...
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `title` | `str` | `None` | Display name for this workflow. |
| `totp_url` | `str` | `None` | URL to fetch TOTP codes for 2FA. |
| `totp_identifier` | `str` | `None` | TOTP credential identifier. |
| `webhook_url` | `str` | `None` | Webhook URL for run completion notifications. |
| `max_steps` | `int` | `None` | Maximum total AI steps for the entire script run. |

<CodeGroup>
```python Python
from skyvern import workflow, run_task

@workflow(title="Search and Extract")
async def run_workflow(parameters: dict):
    result = await run_task(
        prompt="Search for the product and COMPLETE when results appear.",
        url="https://example.com",
        label="search_task",
    )
    return result
```
</CodeGroup>

## @cached decorator

The `@cached` decorator registers a Python function as the cached implementation for a specific workflow block. The `cache_key` must match the `label` of the block it replaces.

```python
from skyvern import cached

# cache_key must match the label of the workflow block being replaced
@cached("my_block_label")
async def my_function(page: SkyvernPage, context: RunContext) -> Any:
    ...
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `cache_key` | `str` | **Required.** The block `label` this function caches. |

The decorated function receives:
- `page: SkyvernPage` — A Playwright-compatible page object for browser interaction.
- `context: RunContext` — The current run context with access to workflow parameters.

<Note>
Cached functions are generated automatically by Skyvern after successful AI runs. You generally do not need to write them by hand. They appear in the Scripts section of the Skyvern UI and can be reviewed, edited, or reset there.
</Note>

<CodeGroup>
```python Python
from skyvern import cached, workflow, run_task
from skyvern import SkyvernPage, RunContext

# Manually written cached function for the "click_download" block.
# This runs instead of the AI agent when the cache is warm.
@cached("click_download")
async def click_download_fn(page: SkyvernPage, context: RunContext):
    await page.click("#download-btn")

@workflow(title="Download Report")
async def run_workflow(parameters: dict):
    # The label matches the @cached key above.
    await run_task(
        prompt='Click the "Download" button.',
        label="click_download",
    )
```
</CodeGroup>

## SkyvernPage

`SkyvernPage` wraps a Playwright `Page` and adds Skyvern-specific helpers. It is passed as the first argument to every `@cached` function.

| Method / Property | Description |
|-------------------|-------------|
| `page.goto(url)` | Navigate to a URL. |
| `page.click(selector)` | Click an element by CSS selector. |
| `page.wait_for_selector(selector)` | Wait for an element to appear. |
| `page.current_label` | The active cache key (set automatically). |
| `page.fill(selector, value, prompt=None, ai="fallback")` | Fill an input. Supports the same selector + prompt + AI fallback as `click`. |
| `page.hover(selector, hold_seconds=0.0)` | Move the mouse over an element, optionally holding for `hold_seconds`. |
| `page.select_option(selector, value, ...)` | Select an option in a `<select>` element. |
| `page.evaluate(expression)` | Run arbitrary JavaScript in the page context. |
| `page.keyboard.press(key)` / `page.keyboard.type(text)` | Low-level keyboard input. |
| `page.get_actual_value(value, totp_identifier, totp_url)` | Resolve a credential reference or TOTP code to its real value. |
| `page.get_totp_digit(context, field_name, digit_index, ...)` | Get a single digit from a TOTP code (for multi-field TOTP inputs). |
| All standard Playwright `Page` methods | Full Playwright async API is available. |

<Note>
`SkyvernPage.click()` and `SkyvernPage.fill()` default to `ai="fallback"`, which tries the CSS selector first, then calls the AI agent if the selector fails or the element is not found. Pass `ai=None` to disable AI fallback entirely. Pass `mode='direct'` for a raw Playwright click with no selector retry or AI fallback.
</Note>

## RunContext

`RunContext` provides access to workflow parameters and upstream block outputs inside a cached function.

| Attribute | Type | Description |
|-----------|------|-------------|
| `context.parameters` | `dict` | All workflow input parameters and upstream block outputs (keyed by `label + "_output"`). |
| `context.page` | `SkyvernPage` | The current browser page. |

<CodeGroup>
```python Python
@cached("process_row")
async def process_row_fn(page: SkyvernPage, context: RunContext):
    # Access a workflow parameter
    row_url = context.parameters.get("current_value")
    await page.goto(row_url)
    await page.click(".submit-btn")
```
</CodeGroup>

## Clearing the cache

If a target website changes and you want to force Skyvern to re-learn from scratch, clear the cached scripts for a specific workflow via the API:

```bash
curl -X DELETE "https://api.skyvern.com/v1/scripts/{workflow_permanent_id}/cache" \
  -H "x-api-key: YOUR_API_KEY"
```

## Disabling caching for a block

To opt a specific block out of caching (always use the AI agent), set `disable_cache: true` in the block definition:

```yaml
- block_type: navigation
  label: tricky_page
  navigation_goal: "Handle the tricky popup and COMPLETE when dismissed."
  disable_cache: true
```

## Conditional branches and progressive caching

`conditional` blocks themselves are **never cached** — they always execute via the AI agent so that branch conditions are evaluated against the actual runtime state. This is intentional.

The blocks **inside** each branch, however, are individually cached the first time that branch executes. Because branches are mutually exclusive, caching is progressive:

- **Run 1** takes branch A → Skyvern caches branch A's child blocks.
- **Run 2** takes branch B → Skyvern caches branch B's child blocks.
- **After both branches have executed at least once**, all children have warm caches and future runs of either path avoid AI calls.

Until a branch has been executed at least once, Skyvern uses the AI agent for that branch's blocks.

```yaml
- block_type: conditional  # ← always runs via AI; never cached
  label: check_status
  branch_conditions:
    - criteria:
        criteria_type: jinja2_template
        expression: "{{ status == 'approved' }}"
      next_block_label: process_approved  # cached after first execution of this branch
    - is_default: true
      next_block_label: handle_pending     # cached after first execution of this branch
```

## Running in code mode (`run_with: code`)

Skyvern Cloud exposes a **Run with Code** toggle in the workflow UI. When enabled, `run_with: code` is set on the run, and Skyvern attempts to execute the entire workflow using cached Python functions without making any AI calls.

**Requirements for a fully cached run:**

- Every top-level block in the workflow must have a cached script with a non-null `run_signature`.
- If **any** block is missing a cached script, Skyvern silently falls back to the AI agent for the entire workflow (not just the missing block).

**Getting there:**

After a successful AI-driven run, Skyvern automatically generates cached scripts for all eligible blocks. After a few successful AI runs — enough for every branch to execute at least once — the workflow can typically run entirely in code mode.

<Note>
The `ai_fallback_triggered` field in the run response indicates whether the cache was bypassed (in full or in part) during that run. If it is `true`, check which blocks lack a cached `run_signature` and run the workflow in AI mode a few more times until all branches have been exercised.
</Note>
