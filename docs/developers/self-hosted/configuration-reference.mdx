Skyvern reads its configuration from a single `Settings` class (`skyvern/config.py`). Every field on that class can be overridden by an environment variable of the same name, an entry in the resolved `.env` file, or a key in the `settings={...}` argument to `Skyvern.local()`. This page is the lookup table: what the field does, what the default is, and which subsystems care about it.

The full list is long — about 230 fields. The tables below group them by subsystem so you can skim the section that matches what you are trying to configure.

<Warning>
Several defaults are placeholder strings that must be replaced before going to production: `SECRET_KEY="PLACEHOLDER"`, `SKYVERN_API_KEY="PLACEHOLDER"`, `ENCRYPTOR_AES_SECRET_KEY="fillmein"`. Skyvern boots with these values, but anything they protect (JWT signing, API auth, credential encryption) is insecure until you set real ones.
</Warning>

## Where settings come from

The `Settings` constructor resolves values in this order, with later sources winning:

1. Field defaults declared in `skyvern/config.py`.
2. The resolved backend `.env` file (typically `~/.skyvern/.env`, see `skyvern/utils/env_paths.py`).
3. Process environment variables.
4. The `settings={...}` keyword argument to `Skyvern.local()`, when used.

Two helpers expose derived state: `Settings.is_sqlite()` returns `True` when `DATABASE_STRING` starts with `sqlite`, and `Settings.is_cloud_environment()` returns `True` when `ENV != "local"` (which forces `EXECUTE_ALL_STEPS=True` regardless of the field value).

On Windows, `model_post_init` rewrites a `postgresql+psycopg://` URL to `postgresql+asyncpg://` because asyncpg is compatible with the Proactor event loop policy and psycopg is not. You do not need to do this rewrite manually.

|---|---|---|
| `ENV` | `local` | `local`, `production`, or `staging`. Drives `is_cloud_environment()` and gates several behaviors. |

## LLM router

The model registry resolves a friendly model name to an internal `LLMConfigRegistry` key via `Settings.get_model_name_to_llm_key()`. The precedence rules are: Vertex AI wins over direct Gemini, Azure wins over direct OpenAI, and Bedrock wins over direct Anthropic, but only when the corresponding `ENABLE_*` flag is set.

| Variable | Default | Description |
|---|---|---|
| `LLM_KEY` | `OPENAI_GPT5_5` | Active LLM. |
| `LLM_API_KEY` | `None` | API key for the active model (when not set per-provider). |
| `SECONDARY_LLM_KEY` | `None` | Lightweight model for cheap calls (planning, classification). |
| `EXTRACTION_LLM_KEY` | `None` | Override for extraction blocks. |
| `SCRIPT_GENERATION_LLM_KEY` | `None` | Override for the script generator. |
| `SCRIPT_REVIEWER_LLM_KEY` | `None` | Override for the script reviewer. |
| `LLM_CONFIG_TIMEOUT` | `300` | LLM call timeout in seconds. |
| `LLM_CONFIG_MAX_TOKENS` | `4096` | Max tokens for a single completion. |
| `LLM_CONFIG_TEMPERATURE` | `0` | Sampling temperature. |
| `LLM_CONFIG_SUPPORT_VISION` | `True` | Whether the active model accepts images. |

Provider feature flags (set the `ENABLE_*` flag and the matching API key):

`ENABLE_OPENAI`, `ENABLE_ANTHROPIC`, `ENABLE_BEDROCK`, `ENABLE_BEDROCK_ANTHROPIC`, `ENABLE_AZURE`, `ENABLE_AZURE_GPT4O_MINI`, `ENABLE_AZURE_O3_MINI`, `ENABLE_AZURE_CUA`, `ENABLE_GEMINI`, `ENABLE_VERTEX_AI`, `ENABLE_OPENAI_COMPATIBLE`. Provider-specific API keys: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, plus the standard AWS / Azure / Vertex auth env vars.
