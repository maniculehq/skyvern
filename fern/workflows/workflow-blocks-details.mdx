Workflow blocks are the building units of Skyvern automations. Each block performs one discrete action. Blocks are chained into a directed graph where outputs from one block feed the inputs of the next.

Every block shares a set of common properties, and each block type adds its own parameters on top of those.

## Common Block Properties

These properties apply to every block type:

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `block_type` | string (enum) | Yes | Identifies the block type (e.g., `task`, `for_loop`). |
| `label` | string | Yes | Unique identifier within this workflow. Used to reference outputs via `{label}_output`. |
| `next_block_label` | string | No | Override the default next block. Used to build non-linear DAGs or connect to `ConditionalBlock` branches. |
| `continue_on_failure` | boolean | No | If `true`, workflow continues to the next block even when this block fails. Default: `false`. |
| `error_code_mapping` | object | No | Map natural-language error conditions to short error codes. Makes downstream error handling deterministic. |
| `disable_cache` | boolean | No | Disable output caching for this specific block execution. |
| `model` | object | No | Override the LLM model for this block. Shape: `{llm_key: "ANTHROPIC_CLAUDE3_5_SONNET"}`. |

### Output parameters

Each block automatically produces an output parameter named `{label}_output`. Reference it in later blocks using `parameter_type: context` and `source_parameter_key: {label}_output`.

## AI Navigation Blocks

### TaskBlock (`block_type: task`)

The primary AI automation block. Skyvern's LLM agent navigates a website, performs actions, and optionally extracts structured data.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `url` | string | Often | Starting URL. Leave blank to continue from where the previous block left off. |
| `navigation_goal` | string | Often | Instructions for what to do on the page. Include explicit `COMPLETE` and `TERMINATE` conditions. |
| `data_extraction_goal` | string | No | What data to extract. Extraction runs after navigation finishes. |
| `data_schema` | object / string | No | JSON Schema describing the shape of the extracted data. |
| `max_retries` | integer | No | Number of step-level retries on transient failure. |
| `max_steps_per_run` | integer | No | Cap the number of browser steps this block may take. |
| `complete_on_download` | boolean | No | Automatically complete when a file download is triggered. |
| `totp_identifier` | string | No | Correlates this block's TOTP request when multiple concurrent tasks share a TOTP provider. |
| `totp_verification_url` | string | No | URL Skyvern calls to fetch the TOTP code when 2FA is required. |
| `complete_criterion` | string | No | Natural-language description of a completion condition (alternative to embedding it in `navigation_goal`). |
| `terminate_criterion` | string | No | Natural-language description of a termination condition. |

```yaml
- block_type: task
  label: login
  parameter_keys:
    - credentials
  url: "{{ website_url }}"
  navigation_goal: >-
    Navigate to the login page and sign in using the provided credentials.
    Dismiss any cookie or promotional popups first.
    COMPLETE when you reach the account dashboard.
    TERMINATE if login fails after three attempts.
  error_code_mapping:
    failed_to_login: Return this error if login was unsuccessful after multiple attempts.
    stuck_with_popups: Return this error if a blocking popup prevents any action.
```

<Note>
**Always include COMPLETE and TERMINATE conditions.** Without explicit stop conditions in `navigation_goal`, the agent will keep taking steps until it exhausts `max_steps_per_run`. Every step counts toward billing.

**Blank `url` continues from the current page.** Skyvern keeps the browser session alive between blocks. If you leave `url` empty, the agent picks up exactly where the previous block left off. Make sure the previous block landed on a useful page.

**`error_code_mapping` shapes your output.** If the agent encounters a condition matching one of your error descriptions, it sets `status: terminated` and returns `{"error": "your_code_key"}` as the output. Downstream code can branch on `{{ taskblock_output.error }}` instead of parsing free-text failure reasons.
</Note>

### NavigationV2Block / TaskV2Block (`block_type: task_v2`)

The next-generation task block powered by the **Skyvern 2.0** engine. Designed for complex, multi-page goals that require deeper reasoning.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | string | Yes | Natural-language instructions. Describes the full goal, not just a single action. |
| `url` | string | No | Starting URL. |
| `totp_identifier` | string | No | TOTP correlation identifier. |
| `totp_verification_url` | string | No | URL Skyvern calls to fetch the TOTP code. |
| `max_iterations` | integer | No | Maximum planning iterations (server default applies if omitted). |
| `max_steps` | integer | No | Maximum browser steps per iteration. |

```yaml
- block_type: task_v2
  label: book_appointment
  url: "https://healthcare-portal.example.com"
  prompt: >-
    Log in and book the earliest available appointment for a general checkup.
    If no appointments are available in the next 30 days, COMPLETE and set
    output to {"status": "no_availability"}.
```

### NavigationBlock (`block_type: navigation`)

Like TaskBlock, but focused exclusively on navigation — no data extraction.

Uses the same parameters as TaskBlock (`url`, `navigation_goal`, `error_code_mapping`, `max_retries`, etc.).

### ActionBlock (`block_type: action`)

Performs exactly **one** browser action (click, type, select, etc.) per execution step.

Uses the same parameters as TaskBlock. Specify a precise `navigation_goal` describing a single action to take.

### ExtractionBlock (`block_type: extraction`)

Extracts structured data from the current page without performing any additional navigation.

Key parameters (same as TaskBlock): `data_extraction_goal`, `data_schema`.

```yaml
- block_type: extraction
  label: extract_product_prices
  data_extraction_goal: >-
    Extract the name, price, and availability of every product listed on this page.
  data_schema:
    type: array
    items:
      type: object
      properties:
        name:
          type: string
        price:
          type: number
        in_stock:
          type: boolean
```

### LoginBlock (`block_type: login`)

Handles login flows with built-in integration with [Skyvern Credentials](/credentials/introduction). Credential values are never sent to the LLM.

Uses the same parameters as TaskBlock. Supply the credential using a `bitwarden_login_credential` or platform credential parameter.

```yaml
parameters:
  - key: site_credentials
    parameter_type: bitwarden_login_credential
    bitwarden_collection_id: "{{ BITWARDEN_COLLECTION_ID }}"
    url_parameter_key: site_url

blocks:
  - block_type: login
    label: authenticate
    parameter_keys:
      - site_credentials
    url: "{{ site_url }}"
    navigation_goal: >-
      Log in using the provided credentials.
      COMPLETE when authenticated. TERMINATE on repeated failure.
```

### ValidationBlock (`block_type: validation`)

Asserts page state before allowing the workflow to continue. If the assertion fails, the workflow terminates (unless `continue_on_failure` is set).

<Warning>
`ValidationBlock` cannot be the first block in a workflow.
</Warning>

Uses the same parameters as TaskBlock. Set `navigation_goal` to a testable condition.

```yaml
- block_type: validation
  label: confirm_checkout_complete
  navigation_goal: >-
    Confirm the page shows an order confirmation message with an order number.
    COMPLETE if confirmed. TERMINATE if no confirmation is visible.
```

---

### FileDownloadBlock (`block_type: file_download`)

Navigates a page and triggers a file download. Use `complete_on_download: true` in a TaskBlock for most download scenarios; this block is for cases where the download is the sole goal.

Uses the same parameters as TaskBlock. The downloaded file is available at `SKYVERN_DOWNLOAD_DIRECTORY`.

## Control Flow Blocks

### ForLoopBlock (`block_type: for_loop`)

Iterates over a list (from a parameter or a previous block's output), executing `loop_blocks` for each item.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `loop_over_parameter_key` | string | Yes | Parameter key holding the list to iterate over. |
| `loop_blocks` | array | Yes | Blocks to execute for each loop item. |
| `continue_on_failure` | boolean | No | If `true`, continue with the next iteration when a loop body block fails. |
| `complete_if_empty` | boolean | No | Complete successfully (instead of failing) when the loop list is empty. Default: `false`. |
| `max_concurrency` | integer | No | Run up to this many iterations in parallel (1–20). Default: `1` (sequential). |

Inside `loop_blocks`, reference the current item via `{{ current_item }}` and the current index via `{{ current_index }}`.

```yaml
- block_type: for_loop
  label: process_orders
  loop_over_parameter_key: order_ids
  continue_on_failure: true
  max_concurrency: 5
  loop_blocks:
    - block_type: task
      label: download_invoice
      complete_on_download: true
      continue_on_failure: true
      url: "{{ order_history_url }}"
      navigation_goal: >-
        Download the invoice for order {{ current_item }}.
        COMPLETE after download is triggered. TERMINATE if no invoice is available.
      error_code_mapping:
        no_invoice: Return if the site does not provide a downloadable invoice.
```

<Tip>
**Concurrency tradeoff:** Each parallel iteration runs in its own isolated browser session. On Skyvern Cloud the sessions are provisioned automatically; on self-hosted deployments make sure your `MAX_BROWSER_INSTANCES` can accommodate `max_concurrency` simultaneous sessions.

**Outputs from failed iterations are `null`.** When `continue_on_failure: true` and an iteration fails, its output entry in the loop result list is `null`. Guard against this in downstream blocks: `{% if item is not none %}`.

**`complete_if_empty` prevents failures on empty lists.** Without it, an empty `loop_over_parameter_key` list raises `NoIterableValueFound` and the workflow fails. Add `complete_if_empty: true` whenever the list may legitimately be empty (e.g., search results with zero matches).

**Loop output shape.** The `for_loop` block's output is a list in the same order as the input. Reference the full list with `{{ process_orders_output }}` or a specific item with `{{ process_orders_output[0] }}`.
</Tip>

### ConditionalBlock (`block_type: conditional`)

Routes execution to different branches based on ordered conditions. The first condition that evaluates to `true` wins.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `branch_conditions` | array of BranchCondition | Yes | Ordered list of conditions. Each condition has a `criteria` object (`criteria_type` + `expression`) and a `next_block_label`. One branch may be marked `is_default: true` as the fallthrough. |

Each `criteria` object:

| Field | Values | Description |
|-------|--------|-------------|
| `criteria_type` | `jinja2_template` \| `prompt` | Evaluation mode. Use `jinja2_template` for expressions; `prompt` for natural-language conditions. |
| `expression` | string | The Jinja2 expression or natural-language description to evaluate. |

```yaml
- block_type: conditional
  label: check_result
  branch_conditions:
    - criteria:
        criteria_type: jinja2_template
        expression: "{{ extract_price_output.price | float < 10.0 }}"
      next_block_label: send_low_price_alert
    - criteria:
        criteria_type: jinja2_template
        expression: "{{ extract_price_output.price | float >= 10.0 }}"
      next_block_label: send_high_price_alert
    - is_default: true
      next_block_label: log_unknown_price
```

<Note>
**First matching branch wins.** Conditions are evaluated in order; the first branch whose criteria evaluates to `true` executes, and all remaining branches are skipped. Put the most specific conditions first.

**`prompt` criteria cost an LLM call.** When `criteria_type: prompt`, Skyvern sends the expression to the configured LLM to evaluate. If your condition is deterministic (comparing numbers, checking strings), prefer `criteria_type: jinja2_template` — it's free and instant.

**Always include a default branch.** If no branch matches and no `is_default: true` branch exists, the workflow terminates with a failure. Add a catch-all default branch even if it just routes to a `wait` or error-handling block.
</Note>

### HumanInteractionBlock (`block_type: human_interaction`)

Pauses the workflow and waits for a human to approve or reject before continuing.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `instructions` | string | No | Message shown to the human reviewer. Default: `"Please review and approve or reject to continue the workflow."`. |
| `positive_descriptor` | string | No | Label for the approval action. Default: `"Approve"`. |
| `negative_descriptor` | string | No | Label for the rejection action. Default: `"Reject"`. |
| `timeout_seconds` | integer | Yes | Time to wait for a response (seconds). On timeout, the workflow terminates. |
| `sender` | string | Yes | Sender address for the notification email. |
| `recipients` | array | Yes | Email addresses to notify when approval is needed. |
| `subject` | string | Yes | Email subject. |
| `body` | string | Yes | Email body. |

```yaml
- block_type: human_interaction
  label: approve_purchase
  instructions: >-
    The agent found a matching item at ${{ price_output.price }}.
    Approve to complete the purchase or reject to cancel.
  sender: automation@example.com
  recipients:
    - manager@example.com
  subject: "Purchase approval needed — ${{ price_output.price }}"
  body: "Please review and approve or reject the pending purchase."
  timeout_seconds: 3600
```

### WorkflowTriggerBlock (`block_type: workflow_trigger`)

Triggers a child workflow from within a parent workflow. Supports passing parameters and optionally waiting for the child to finish.

<Note>
Maximum workflow nesting depth is 10 levels.
</Note>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `workflow_permanent_id` | string | Yes | The permanent ID of the workflow to trigger. |
| `payload` | object | No | Key-value parameters passed to the child workflow. Supports Jinja2 templates. |
| `wait_for_completion` | boolean | No | Wait for the child workflow to finish before continuing. Default: `true`. |
| `use_parent_browser_session` | boolean | No | Share the parent's browser session with the child workflow. Default: `false`. |
| `browser_session_id` | string | No | Pass a specific browser session ID to the child workflow. |

```yaml
- block_type: workflow_trigger
  label: run_child_workflow
  workflow_permanent_id: "wpid_abc123"
  payload:
    start_date: "{{ report_date }}"
    target_url: "{{ site_url }}"
  wait_for_completion: true
```

## Data & AI Blocks

### CodeBlock (`block_type: code`)

Executes custom Python code inside a sandboxed environment. Can access workflow parameters and interact with the browser page via `page`.

<Note>
`CodeBlock` is an **invite-only** feature on Skyvern Cloud. Contact [support@skyvern.com](mailto:support@skyvern.com) to request access.
</Note>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `code` | string | Yes | Python code to execute. Must set a `result` variable; this becomes the block output. |
| `parameter_keys` | array | No | Parameters available as local variables in the code. |

**Available variables:**

| Variable | Type | Description |
|----------|------|-------------|
| `page` | `playwright.async_api.Page` | The current browser page. Use `await page.goto(url)`, `await page.title()`, etc. |
| Each key in `parameter_keys` | Any | Resolved parameter value, available as a local variable. |

**Available built-ins:** `print`, `len`, `range`, `str`, `int`, `float`, `dict`, `list`, `tuple`, `set`, `bool`, `sleep` (alias for `asyncio.sleep`), `asyncio.sleep`, `re.match`/`search`/`findall`/`sub`/`compile`/`split`, `json.dumps`/`json.loads`, `Exception`.

**Block output:** The entire local-variable scope at the end of execution is captured and becomes the block output (a dict). Assign to `result` — downstream blocks reference it as `{{ label_output.result }}`.

**Security restrictions:** No `import` statements. No subprocess, OS, or filesystem access. No dunder attributes (`__class__`, `__globals__`, etc.). No `eval`, `exec`, or `compile`.

<Warning>
The sandbox is a defense-in-depth layer implemented via an AST blocklist, not full process isolation. Use CodeBlock only for trusted workflow authors.
</Warning>

```yaml
- block_type: code
  label: calculate_diff
  parameter_keys:
    - alibaba_price
    - amazon_price
  code: |
    if alibaba_price["unitPrice"] and amazon_price["unitPrice"]:
        result = (alibaba_price["unitPrice"] - amazon_price["unitPrice"]) / amazon_price["unitPrice"]
    else:
        result = None
```

```yaml
# Browser interaction example
- block_type: code
  label: capture_tab_url
  code: |
    result = {
        "url": page.url,
        "title": await page.title(),
    }
```

### TextPromptBlock (`block_type: text_prompt`)

Sends a prompt to a language model and returns structured output. No browser interaction occurs.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | string | Yes | The prompt to send. Supports Jinja2 templates using `parameter_keys`. |
| `json_schema` | object | No | JSON Schema for the LLM response. Enforces structured output. |
| `llm_key` | string | No | Override which LLM to use (e.g., `OPENAI_GPT4O`, `ANTHROPIC_CLAUDE3_5_SONNET`). |
| `parameter_keys` | array | No | Parameters available as Jinja2 variables in the prompt. |

```yaml
- block_type: text_prompt
  label: generate_summary
  parameter_keys:
    - extracted_data
  llm_key: OPENAI_GPT4O
  prompt: >-
    You are a data analyst. Summarize the following product data in one sentence:
    {{ extracted_data | tojson }}
  json_schema:
    type: object
    properties:
      summary:
        type: string
      sentiment:
        type: string
        enum: [positive, neutral, negative]
```

### FileParserBlock (`block_type: file_url_parser`)

Downloads a file from a URL and uses an LLM to parse and extract structured data from it.

**Supported file types:** PDF, Excel (`.xlsx`, `.xls`, `.xlsm`), CSV/TSV, Word (`.docx`), images (PNG, JPG, GIF, BMP, WebP, TIFF).

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `file_url` | string | Yes | URL of the file to download and parse. |
| `file_type` | string (enum) | Yes | One of: `pdf`, `excel`, `csv`, `docx`, `image`. |
| `json_schema` | object | No | Schema describing the structured output to extract from the file. |

```yaml
- block_type: file_url_parser
  label: parse_invoice
  file_url: "{{ invoice_download_url }}"
  file_type: pdf
  json_schema:
    type: object
    properties:
      invoice_number:
        type: string
      total_amount:
        type: number
      line_items:
        type: array
        items:
          type: object
          properties:
            description:
              type: string
            amount:
              type: number
```

### HttpRequestBlock (`block_type: http_request`)

Makes an HTTP request to any URL. Safe for secrets — parameter values are sent directly and never passed to the LLM.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `method` | string | Yes | HTTP method: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`. |
| `url` | string | Yes | Request URL. Supports Jinja2 templates. |
| `headers` | object | No | HTTP request headers. |
| `body` | object | No | Request body (serialized as JSON automatically). |
| `files` | object | No | Multipart file upload. Keys are field names; values are local file paths. |
| `timeout` | integer | No | Request timeout in seconds. Default: `30`. |
| `follow_redirects` | boolean | No | Follow HTTP redirects. Default: `true`. |
| `download_filename` | string | No | Save response body as a file with this name. |
| `save_response_as_file` | boolean | No | Save the raw response body as a file artifact. |
| `parameter_keys` | array | No | Parameters available as Jinja2 variables in `url`, `headers`, `body`. |

```yaml
- block_type: http_request
  label: notify_webhook
  method: POST
  url: "https://hooks.example.com/notify"
  headers:
    Authorization: "Bearer {{ api_token }}"
    Content-Type: application/json
  body:
    event: workflow_complete
    order_id: "{{ order_id }}"
    result: "{{ extract_output }}"
  timeout: 15
```

### SendEmailBlock (`block_type: send_email`)

Sends an email via SMTP, optionally attaching downloaded files.

SMTP credentials should be stored as AWS Secrets Manager secrets and referenced via `aws_secret` parameters.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `smtp_host_secret_parameter_key` | string | Yes | Parameter key for the SMTP host (AWS secret). |
| `smtp_port_secret_parameter_key` | string | Yes | Parameter key for the SMTP port (AWS secret). |
| `smtp_username_secret_parameter_key` | string | Yes | Parameter key for the SMTP username (AWS secret). |
| `smtp_password_secret_parameter_key` | string | Yes | Parameter key for the SMTP password (AWS secret). |
| `sender` | string | Yes | From address. |
| `recipients` | array | Yes | List of recipient email addresses. |
| `subject` | string | Yes | Email subject. Supports Jinja2 templates. |
| `body` | string | No | Email body text. Supports Jinja2 templates. |
| `file_attachments` | array | No | List of local file paths to attach. Use `SKYVERN_DOWNLOAD_DIRECTORY` to attach all downloaded files. |

```yaml
parameters:
  - key: smtp_host
    parameter_type: aws_secret
    aws_key: MY_SMTP_HOST
  - key: smtp_port
    parameter_type: aws_secret
    aws_key: MY_SMTP_PORT
  - key: smtp_username
    parameter_type: aws_secret
    aws_key: MY_SMTP_USERNAME
  - key: smtp_password
    parameter_type: aws_secret
    aws_key: MY_SMTP_PASSWORD

blocks:
  - block_type: send_email
    label: email_report
    smtp_host_secret_parameter_key: smtp_host
    smtp_port_secret_parameter_key: smtp_port
    smtp_username_secret_parameter_key: smtp_username
    smtp_password_secret_parameter_key: smtp_password
    sender: reports@example.com
    recipients:
      - team@example.com
    subject: "Daily Report — {{ current_date }}"
    body: "Please find today's report attached."
    file_attachments:
      - SKYVERN_DOWNLOAD_DIRECTORY
```

### FileUploadBlock (`block_type: file_upload`)

Uploads files to AWS S3 or Azure Blob Storage with explicit credentials.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `storage_type` | string | Yes | `s3` or `azure`. |
| `path` | string | Yes | Local path to upload. Use `SKYVERN_DOWNLOAD_DIRECTORY` for downloaded files. |
| `s3_bucket` | string | S3 only | S3 bucket name. |
| `aws_access_key_id` | string | S3 only | AWS access key ID. |
| `aws_secret_access_key` | string | S3 only | AWS secret access key. |
| `region_name` | string | S3 only | AWS region (e.g., `us-east-1`). |
| `azure_storage_account_name` | string | Azure only | Azure Storage account name. |
| `azure_storage_account_key` | string | Azure only | Azure Storage account key. |
| `azure_blob_container_name` | string | Azure only | Azure Blob container name. |

```yaml
- block_type: file_upload
  label: upload_to_s3
  storage_type: s3
  path: SKYVERN_DOWNLOAD_DIRECTORY
  s3_bucket: my-skyvern-bucket
  aws_access_key_id: "{{ aws_key_id }}"
  aws_secret_access_key: "{{ aws_secret_key }}"
  region_name: us-east-1
```

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": "arn:aws:s3:::my-skyvern-bucket/*"
    }
  ]
}
```

### PrintPageBlock (`block_type: print_page`)

Converts the current browser page to a PDF and saves it as a workflow artifact.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `format` | string | No | Paper format: `A4`, `Letter`, `Legal`, `Tabloid`. Default: `A4`. |
| `landscape` | boolean | No | Landscape orientation. Default: `false`. |
| `print_background` | boolean | No | Include background colors and images. Default: `true`. |
| `include_timestamp` | boolean | No | Add date/time headers and footers. Default: `true`. |
| `custom_filename` | string | No | Custom filename for the saved PDF. |

```yaml
- block_type: print_page
  label: save_confirmation_pdf
  format: Letter
  landscape: false
  custom_filename: "order_confirmation_{{ current_date }}.pdf"
```

## Common patterns and gotchas

### Pattern: Handling empty search results in a loop

When you loop over search results, the list may be empty. Combine `complete_if_empty` with a `ConditionalBlock` to branch cleanly:

```yaml
blocks:
  - block_type: extraction
    label: search_results
    data_extraction_goal: Extract all matching order IDs from the page.
    data_schema:
      type: array
      items:
        type: string

  - block_type: for_loop
    label: process_each_order
    loop_over_parameter_key: search_results_output
    complete_if_empty: true
    continue_on_failure: true
    loop_blocks:
      - block_type: task
        label: download_order_invoice
        complete_on_download: true
        navigation_goal: >-
          Download the invoice for order {{ current_item }}.
          COMPLETE after download starts. TERMINATE if no invoice link is visible.
```

### Pattern: Two-engine workflow (fast navigation + deep extraction)

Use `skyvern-1.0` for simple navigation steps and `task_v2` for complex multi-page reasoning:

```yaml
blocks:
  # Fast login with skyvern-1.0
  - block_type: login
    label: authenticate
    parameter_keys:
      - site_credentials
    url: "{{ site_url }}"
    navigation_goal: >-
      Log in using the provided credentials.
      COMPLETE when the dashboard is shown. TERMINATE after three failed attempts.

  # Deep reasoning task with task_v2
  - block_type: task_v2
    label: find_and_book
    prompt: >-
      Find the cheapest available flight from {{ origin }} to {{ destination }}
      departing on {{ departure_date }}, select it, and proceed through the booking
      flow until the payment page. Stop before entering any payment details.
      Return {"flight_price": <price>, "airline": <airline>}.
```

### Gotcha: Block labels must be unique within a workflow

Each block's `label` is used as a namespace for its output (`{{ label_output }}`). Duplicate labels cause unpredictable output routing. Labels must also be valid Python identifiers — no hyphens, no spaces.

### Gotcha: `continue_on_failure` interacts with the next block

When `continue_on_failure: true` on a block, execution always proceeds to the next block regardless of the block's success status. The output parameter is still set (to `null` if the block failed). A `ValidationBlock` immediately after will see the prior block's (possibly null) output.

### Gotcha: Jinja2 strict mode and missing variables

Block string fields use Jinja2 with `StrictUndefined`. Referencing a variable that doesn't exist (including a misspelled parameter key or a block label that hasn't run yet) raises a template error and fails the block. If a variable may not be set, use Jinja2's `default` filter: `{{ some_var | default("") }}`.

## Parameter Types Reference

Workflow parameters supply values to blocks. Declare them in the `parameters` section of the workflow definition.

| `parameter_type` | Description |
|------------------|-------------|
| `workflow` | Value passed in at runtime via the Run Workflow API. |
| `context` | Value taken from a previous block's output. Requires `source_parameter_key`. |
| `aws_secret` | Value fetched from AWS Secrets Manager. Requires `aws_key`. |
| `bitwarden_login_credential` | Credential fetched from Bitwarden. Requires collection and item config. |
| `output` | Alias for `context` in some older workflow definitions. |

## Jinja2 Template Reference

Block string fields support Jinja2 templating for dynamic values:

| Template | Resolves to |
|----------|-------------|
| `{{ parameter_name }}` | Value of a declared parameter. |
| `{{ block_label_output }}` | Full output object of a previous block. |
| `{{ block_label_output.field }}` | Specific field from a block's output. |
| `{{ current_item }}` | Current loop item inside `ForLoopBlock`. |
| `{{ current_index }}` | Zero-based index of the current loop iteration. |
| `{{ current_value }}` | Alias for `current_item`. |
| `{{ current_date }}` | Today's date in `YYYY-MM-DD` format. |
| `{{ workflow_id }}` | Permanent ID of the running workflow. |
| `{{ workflow_run_id }}` | ID of the current workflow run. |
| `{{ value \| json }}` | Inject `value` as a native JSON type (preserves booleans, integers, etc.). |
| `{{ value \| tojson }}` | Serialize `value` to a JSON string. |
