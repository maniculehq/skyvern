The `@skyvern/client` TypeScript SDK (located in `skyvern-ts/client/`) has an 18-file Vitest test suite split into two projects: **unit** tests for HTTP infrastructure and **wire** tests that validate the SDK against a mock HTTP server. This guide explains how to run both, what they cover, and how to write custom tests.

## Prerequisites

- **Node.js ≥ 18** (the TS SDK target; Node.js 20 recommended to match the rest of the repo)
- **pnpm 10.14.0** — the SDK uses pnpm as its package manager

Install pnpm if you don't have it:

```bash
npm install -g pnpm@10.14.0
```

Install dependencies from `skyvern-ts/client/`:

```bash
cd skyvern-ts/client
pnpm install
```

## Running the tests

All commands run from `skyvern-ts/client/`.

| Command | What runs |
|---------|-----------|
| `pnpm test` | Both unit and wire projects |
| `pnpm test:unit` | Unit project only (`vitest --project unit`) |
| `pnpm test:wire` | Wire project only (`vitest --project wire`) |

```bash
# Run everything
pnpm test

# Run only unit tests (faster, no mock server spin-up)
pnpm test:unit

# Run only wire tests (API contract tests)
pnpm test:wire
```

## Unit tests

Unit tests are in `tests/unit/` and cover the Fern-generated HTTP fetcher infrastructure that underlies every SDK call. They run in a Node environment with no external dependencies.

### Unit test inventory

**`tests/unit/fetcher/`** — 9 files covering the HTTP fetcher layer

| File | Subject |
|------|---------|
| `Fetcher.test.ts` | Top-level `fetcherImpl` function — request dispatch and response routing |
| `HttpResponsePromise.test.ts` | Promise wrapper that exposes typed `.json()` / `.stream()` / `.blob()` |
| `RawResponse.test.ts` | Raw response passthrough (status, headers, body) |
| `createRequestUrl.test.ts` | URL construction from base URL, path, and query parameters |
| `getRequestBody.test.ts` | Serialises request bodies (JSON, form-data, binary) |
| `getResponseBody.test.ts` | Deserialises response bodies with content-type negotiation |
| `makeRequest.test.ts` | End-to-end request/response cycle through the fetcher |
| `requestWithRetries.test.ts` | Retry logic — exponential back-off, status-code filtering |
| `signals.test.ts` | `AbortSignal` propagation and cancellation behaviour |

**`tests/unit/file/`**

| File | Subject |
|------|---------|
| `file.test.ts` | File upload encoding — binary buffers, `Blob`, multipart boundaries |

**`tests/unit/form-data-utils/`** — 2 files

| File | Subject |
|------|---------|
| `encodeAsFormParameter.test.ts` | Encodes primitives, arrays, and nested objects as form parameters |
| `formDataWrapper.test.ts` | Cross-platform `FormData` wrapper (browser vs Node differences) |

**`tests/unit/url/`** — 2 files

| File | Subject |
|------|---------|
| `join.test.ts` | URL segment joining with slash normalisation |
| `qs.test.ts` | Query-string serialisation — arrays, booleans, `undefined` omission |

## Wire tests

Wire tests are in `tests/wire/` and validate the generated `SkyvernClient` against a local mock HTTP server. They use [MSW (Mock Service Worker)](https://mswjs.io/) running in Node mode — no live Skyvern server is needed.

### How the mock server works

The mock server infrastructure lives in `tests/mock-server/`:

- **`MockServerPool.ts`** — manages a shared MSW server instance shared across test files
- **`MockServer.ts`** — per-test server context with typed endpoint builders
- **`mockEndpointBuilder.ts`** — fluent API for registering expected request/response pairs
- **`setup.ts`** — Vitest `beforeAll`/`afterAll` hooks that call `mockServerPool.listen()` and `mockServerPool.close()`

Each wire test creates a `SkyvernClient` pointing at `server.baseUrl` (a random local port), registers expected endpoints, then calls the client methods and asserts responses.

```typescript
// Simplified example of the wire test pattern
const { client, server } = await mockServerPool.start();

server.mockEndpoint({
  method: "POST",
  path: "/v1/run/tasks",
  response: { run_id: "run_abc123", status: "queued" },
});

const result = await client.agent.runTask({ prompt: "test" });
expect(result.runId).toBe("run_abc123");
```

### Wire test inventory

| File | What it covers |
|------|---------------|
| `tests/wire/main.test.ts` | Comprehensive happy-path tests for all Skyvern REST API endpoints (~41 KB; auto-generated by Fern) |
| `tests/wire/artifacts.test.ts` | Artifact download and upload endpoints |
| `tests/wire/scripts.test.ts` | Script management endpoints (create, deploy, run) |

<Note>
The wire tests are generated by Fern from the OpenAPI spec. Do not edit `main.test.ts`, `artifacts.test.ts`, or `scripts.test.ts` directly — changes will be overwritten on the next `fern generate` run.
</Note>

## Adding custom tests

`tests/custom.test.ts` is the designated location for hand-written SDK tests. It is listed in `.fernignore` so Fern will never overwrite it.

To add custom tests:

1. Open `tests/custom.test.ts`
2. Replace or extend the placeholder `describe` block:

```typescript
import { SkyvernClient } from "../src";

describe("custom tests", () => {
  it("initialises a client with an API key", () => {
    const client = new SkyvernClient({ apiKey: "test-key" });
    expect(client).toBeDefined();
  });

  it("sends the correct Authorization header", async () => {
    // Use MockServerPool for any tests that need HTTP assertions
    // (see wire test pattern above)
  });
});
```

The `custom.test.ts` file is picked up by the **unit** project (it sits in the `tests/` root, which the unit project includes via `include: ["**/*.test.{js,ts,jsx,tsx}"]`).

## Configuration reference

`skyvern-ts/client/vitest.config.ts`:

```typescript
import { defineConfig } from "vitest/config";

export default defineConfig({
  test: {
    projects: [
      {
        test: {
          globals: true,        // No need to import describe/it/expect
          name: "unit",
          environment: "node",
          root: "./tests",
          include: ["**/*.test.{js,ts,jsx,tsx}"],
          exclude: ["wire/**"], // Wire tests excluded from unit project
        },
      },
      {
        test: {
          globals: true,
          name: "wire",
          environment: "node",
          root: "./tests/wire",
          setupFiles: ["../mock-server/setup.ts"], // Starts MSW before tests
        },
      },
    ],
    passWithNoTests: true,
  },
});
```

Key points:
- **`globals: true`** — `describe`, `it`, `expect`, and other Vitest globals are injected automatically; no import needed in generated test files (though custom files may import them explicitly).
- **Dual-project setup** — `pnpm test:unit` and `pnpm test:wire` run isolated subsets; `pnpm test` runs both.
- **`passWithNoTests: true`** — the test run does not fail if no files match.
