All Skyvern settings are controlled through environment variables. Set them in a `.env` file in your project root, or export them in your shell before starting the service.

Variables are read by `skyvern/config.py` using [pydantic-settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/). Any variable not set uses the documented default.

---

## Core / Server

| Variable | Default | Description |
|---|---|---|
| `ENV` | `local` | Environment name. Common values: `local`, `staging`, `prod`. Affects CORS, logging, and session behavior |
| `PORT` | `8000` | API server port |
| `SECRET_KEY` | `PLACEHOLDER` | JWT signing secret. **Generate a secure random value for any non-local deployment.** Example: `openssl rand -hex 32` |
| `ALLOWED_ORIGINS` | `["*"]` | CORS allowed origins as a JSON list. Restrict this in production: `["https://your-domain.com"]` |
| `ALLOWED_HOSTS` | `[]` | HTTP Host header allowlist. Empty means all hosts are allowed |
| `BLOCKED_HOSTS` | `["localhost"]` | Domain names that are blocked as webhook callback URLs and credential service endpoints. Private IP ranges (`10.x`, `172.16.x`, `192.168.x`, loopback) are always blocked regardless of this list. Add to `ALLOWED_HOSTS` to unblock a specific host for internal deployments |
| `LOG_LEVEL` | `INFO` | Logging verbosity: `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `JSON_LOGGING` | `false` | Emit structured JSON log lines (recommended for log aggregation pipelines) |

## Database

| Variable | Default | Description |
|---|---|---|
| `DATABASE_STRING` | `sqlite+aiosqlite:///$HOME/.skyvern/data.db` | Primary database connection URL. For production PostgreSQL: `postgresql+psycopg://user:pass@host:5432/dbname`. The SQLite default works out of the box for local dev |
| `DATABASE_REPLICA_STRING` | _(none)_ | Read replica DSN. When set, read queries are routed to this database |
| `DATABASE_STATEMENT_TIMEOUT_MS` | `60000` | Query timeout in milliseconds before Skyvern cancels a slow query |
| `DATABASE_POOL_SIZE` | `5` | SQLAlchemy connection pool size |
| `DATABASE_POOL_MAX_OVERFLOW` | `10` | Maximum overflow connections above `DATABASE_POOL_SIZE` |
| `DISABLE_CONNECTION_POOL` | `false` | Disable connection pooling (useful for PgBouncer in transaction mode) |

**Docker Compose default:**
```bash
DATABASE_STRING=postgresql+psycopg://skyvern:skyvern@postgres:5432/skyvern
```

## LLM

### Provider selection

| Variable | Default | Description |
|---|---|---|
| `LLM_KEY` | `OPENAI_GPT4O` | Primary model key. See supported values below |
| `SECONDARY_LLM_KEY` | _(none)_ | Lightweight model for simple agent operations (classification, short prompts) |
| `LLM_API_KEY` | _(none)_ | Generic API key for custom or OpenAI-compatible model configs |

**Supported `LLM_KEY` values** (common options):

| Value | Provider | Model |
|---|---|---|
| `OPENAI_GPT4O` | OpenAI | GPT-4o |
| `OPENAI_GPT4O_MINI` | OpenAI | GPT-4o mini |
| `ANTHROPIC_CLAUDE3.5_SONNET` | Anthropic | Claude 3.5 Sonnet |
| `ANTHROPIC_CLAUDE3_OPUS` | Anthropic | Claude 3 Opus |
| `GEMINI_FLASH` | Google | Gemini Flash |
| `AZURE_OPENAI` | Azure | Configured Azure OpenAI deployment |

### Provider activation flags

Set the `ENABLE_*` flag to `true` for your provider, then supply the API key.

| Variable | Default | Description |
|---|---|---|
| `ENABLE_OPENAI` | `false` | Enable OpenAI provider |
| `ENABLE_ANTHROPIC` | `false` | Enable Anthropic provider |
| `ENABLE_GEMINI` | `false` | Enable Google Gemini provider |
| `ENABLE_AZURE` | `false` | Enable Azure OpenAI provider |
| `ENABLE_BEDROCK` | `false` | Enable AWS Bedrock provider |
| `ENABLE_VERTEX_AI` | `false` | Enable Google Vertex AI provider |
| `ENABLE_VOLCENGINE` | `false` | Enable Volcengine (Doubao/UI-TARS) provider |
| `ENABLE_OLLAMA` | `false` | Enable Ollama for local models |
| `ENABLE_OPENAI_COMPATIBLE` | `false` | Enable any OpenAI-compatible API endpoint |

### Provider API keys

| Variable | Description |
|---|---|
| `OPENAI_API_KEY` | OpenAI API key (required when `ENABLE_OPENAI=true`) |
| `ANTHROPIC_API_KEY` | Anthropic API key (required when `ENABLE_ANTHROPIC=true`) |
| `GEMINI_API_KEY` | Google Gemini API key (required when `ENABLE_GEMINI=true`) |
| `VOLCENGINE_API_KEY` | Doubao API key for UI-TARS engine (required when `ENABLE_VOLCENGINE=true`) |

## Browser

| Variable | Default | Description |
|---|---|---|
| `BROWSER_TYPE` | `chromium-headful` | Browser launch mode. Options: `chromium-headful` (visible window), `chromium-headless` (no window, good for servers), `cdp-connect` (attach to existing browser via CDP) |
| `BROWSER_REMOTE_DEBUGGING_URL` | `http://127.0.0.1:9222` | CDP URL when `BROWSER_TYPE=cdp-connect` |
| `CHROME_EXECUTABLE_PATH` | _(none)_ | Path to a specific Chrome/Chromium binary. When set with `BROWSER_TYPE=cdp-connect`, Skyvern launches this binary |
| `MAX_STEPS_PER_RUN` | `10` | Maximum steps a task can take before failing. **The default of 10 is intentionally conservative.** Simple form fills usually need 3–8 steps; complex multi-page tasks may need 20–50. Raise this (e.g., `50`) for complex tasks. You are charged per step, so set a reasonable upper bound |
| `BROWSER_ACTION_TIMEOUT_MS` | `5000` | Timeout for individual element interactions (click, fill, etc.) in milliseconds |
| `BROWSER_LOADING_TIMEOUT_MS` | `60000` | Page load timeout in milliseconds |
| `BROWSER_SCREENSHOT_TIMEOUT_MS` | `20000` | Screenshot capture timeout in milliseconds |
| `BROWSER_WIDTH` | `1920` | Browser viewport width in pixels |
| `BROWSER_HEIGHT` | `1080` | Browser viewport height in pixels |
| `BROWSER_TIMEZONE` | `America/New_York` | Browser timezone (affects JavaScript `Date` and locale-sensitive sites) |
| `BROWSER_LOCALE` | _(system default)_ | Browser locale string (e.g. `en-US`, `de-DE`). Null uses the system locale |

**Use your own Chrome browser:**
```bash
BROWSER_TYPE=cdp-connect
CHROME_EXECUTABLE_PATH=/Applications/Google Chrome.app/Contents/MacOS/Google Chrome
```

## Storage (artifacts)

Skyvern stores screenshots, HAR files, and other artifacts from task runs.

| Variable | Default | Description |
|---|---|---|
| `SKYVERN_STORAGE_TYPE` | `local` | Storage backend. Options: `local`, `s3cloud`, `azureblob` |
| `ARTIFACT_STORAGE_PATH` | `skyvern/artifacts` | Local filesystem path for artifacts (used when `SKYVERN_STORAGE_TYPE=local`) |

### S3 storage (`SKYVERN_STORAGE_TYPE=s3cloud`)

| Variable | Default | Description |
|---|---|---|
| `AWS_REGION` | `us-east-1` | AWS region |
| `AWS_S3_BUCKET_ARTIFACTS` | `skyvern-artifacts` | S3 bucket for artifacts (HAR, logs) |
| `AWS_S3_BUCKET_SCREENSHOTS` | `skyvern-screenshots` | S3 bucket for screenshots |

### Azure Blob Storage (`SKYVERN_STORAGE_TYPE=azureblob`)

| Variable | Default | Description |
|---|---|---|
| `AZURE_STORAGE_ACCOUNT_NAME` | _(none)_ | Azure storage account name |
| `AZURE_STORAGE_ACCOUNT_KEY` | _(none)_ | Azure storage account key |
| `AZURE_STORAGE_CONTAINER_ARTIFACTS` | `skyvern-artifacts` | Container for artifacts |
| `AZURE_STORAGE_CONTAINER_SCREENSHOTS` | `skyvern-screenshots` | Container for screenshots |

## Workflow settings

| Variable | Default | Description |
|---|---|---|
| `WORKFLOW_WAIT_BLOCK_MAX_SEC` | `1800` | Maximum seconds a WaitBlock can pause a workflow (default 30 minutes) |
| `WORKFLOW_TEMPLATING_STRICTNESS` | `lax` | Jinja template error handling. `lax` silently substitutes an empty string for undefined variables — useful during development. `strict` raises an error on any undefined variable — recommended for production to catch mis-spelled parameter keys early |
| `MAX_STEPS_PER_TASK_V2` | `25` | Step limit for the Skyvern 2.0 engine per iteration |
| `MAX_ITERATIONS_PER_TASK_V2` | `10` | Iteration limit for the Skyvern 2.0 engine per task |

## Common gotchas

### Tasks fail with "Max steps exceeded"

The default `MAX_STEPS_PER_RUN=10` is low. If your tasks involve multiple pages or require more than ~8 actions, increase this:

```bash
MAX_STEPS_PER_RUN=50
```

### Webhook callbacks return 400 "blocked host"

By default, `BLOCKED_HOSTS=["localhost"]` and all private IP ranges (`10.x`, `172.x`, `192.168.x`, loopback) are blocked as webhook targets. If you run your webhook receiver on a private network, add the host to `ALLOWED_HOSTS`:

```bash
ALLOWED_HOSTS=["my-internal-host.company.internal"]
```

`ALLOWED_HOSTS` is a whitelist: hosts in this list bypass both the `BLOCKED_HOSTS` check and the private-IP block.

### Workflow parameters silently empty in `lax` mode

With `WORKFLOW_TEMPLATING_STRICTNESS=lax` (the default), a typo in a parameter key (`{{sarch_query}}` instead of `{{search_query}}`) renders as an empty string with no error. Switch to `strict` in production to catch these early:

```bash
WORKFLOW_TEMPLATING_STRICTNESS=strict
```

### SQLite is not suitable for concurrent workflows

The default SQLite backend (`~/.skyvern/data.db`) serializes all writes. Running multiple concurrent workflows will work but may be slow. Switch to PostgreSQL for any multi-user or high-throughput deployment.

## Example `.env` for Docker Compose

```bash
# Database
DATABASE_STRING=postgresql+psycopg://skyvern:skyvern@postgres:5432/skyvern

# Server
ENV=prod
SECRET_KEY=change-me-use-openssl-rand-hex-32
SKYVERN_API_KEY=my-secure-local-api-key
ALLOWED_ORIGINS=["https://your-domain.com"]

# Browser
BROWSER_TYPE=chromium-headful

# LLM (choose one provider)
ENABLE_OPENAI=true
LLM_KEY=OPENAI_GPT4O
OPENAI_API_KEY=sk-...

# Logging
LOG_LEVEL=INFO
JSON_LOGGING=true

# Storage
SKYVERN_STORAGE_TYPE=s3cloud
AWS_REGION=us-east-1
AWS_S3_BUCKET_ARTIFACTS=my-skyvern-artifacts
AWS_S3_BUCKET_SCREENSHOTS=my-skyvern-screenshots
```
